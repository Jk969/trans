# Trans — 局域网传输站 产品规划（v0.3）

> 个人使用的局域网文件/文本传输服务。电脑端托盘常驻，手机扫码用网页，免安装、免登录。
> 工作目录：`D:\dev\zcode\trans`
>
> **v0.3 变更（评审结论）：**
> 1. 二维码改由**后端枚举网卡**生成 access_url，前端不再用 location.href（会扫出 localhost）
> 2. 砍掉"网页拖拽 + WS 按需取流"作为 MVP 核心；拖拽上架改为**流式落盘到暂存缓存**，零拷贝只保留给 SendTo / 复制文件的**路径引用**
> 3. 定性为**登录后自启的托盘常驻程序**，不注册 Windows Service（Session 0 拿不到桌面剪贴板/托盘/SendTo）
> 4. HTTP 非安全上下文下 PWA/剪贴板能力**降预期**：只承诺"主屏幕快捷方式"，复制一律按钮 + execCommand 兜底
> 5. **暂存架与剪贴板墙合并为"传输流"**：文件传输助手式混合时间流，底部 Tab 只留 传输/文件，上传降为全局按钮
> 6. 新增异常状态表与防污染/防回环细节；版本规划按"一条闭环"重排

---

## 1. 定位与心智模型

**一句话定位**：手机扫码，电脑变"文件传输助手 + 影音站"。

**心智模型只有一个**：像微信文件传输助手，**给自己发东西**。文件、照片、文字，全都进同一条时间流（传输流）。不区分"这是文件功能""那是剪贴板功能"。

设计原则：**高频动作 ≤ 2 步**；异常路径优先于顺利路径设计（见 §5）。

非目标：公网访问、多用户权限、大并发、加密传输、转码集群、离线 PWA。

---

## 2. 核心场景

| # | 场景 | 方向 | 主路径 |
|---|------|------|--------|
| 1 | 传输流（文本+文件混合时间流） | 双向 | 拖拽/右键上架、发送文字，对端即见；PC 端一键写入系统剪贴板 |
| 2 | 视频观看 | PC → 手机 | 传输流/文件里点开即播（Range 流式） |
| 3 | 手机上传 | 手机 → PC | 发到传输流（免选路径）或指定目录 |
| 4 | 文件浏览 | PC → 手机 | 兜底入口 + 搜索，不再是主路径 |

## 3. 使用方式（用户旅程）

### 3.1 电脑端：托盘常驻程序（不是 Windows Service）

```
登录 Windows 后自启（注册表 Run 键，非服务）
   │
   ├─ 启动 HTTP 服务（默认 :8020）
   ├─ 枚举网卡 → 筛私网 IPv4 → 生成 access_url 列表
   ├─ 首次运行：自动弹浏览器打开主页 + 引导防火墙/专用网络
   └─ 常驻系统托盘
        右键：打开主页 / 暂停服务 / 暂停剪贴板监听10分钟 / 退出 / 设置
```

- 为什么不做 Windows Service：Service 在 Session 0，拿不到用户桌面剪贴板、托盘图标、SendTo 转发、用户目录权限，全案一半功能会坏。**托盘常驻 + 登录后自启**是唯一正解（代价：未登录时手机不可访问，个人场景可接受）。
- 单实例锁 + IPC（named pipe）：SendTo 右键会把 exe 再拉起一次，必须转发参数给已运行实例。

### 3.2 手机端

```
扫码 → 打开网页（免装 App、免登录）
   │
   ├─ 首屏 = 传输流（实时 WS 同步）
   ├─ 底部 Tab：传输 / 文件；右下角全局 ⊕ 上传按钮
   ├─ 可"添加到主屏幕"= 普通快捷方式（不承诺离线/后台/推送）
   └─ 打不开 → 独立断连页（不是转圈），见 §5
```

## 4. 交互设计

### 4.1 连接与二维码

- **后端枚举网卡**，筛私网 IPv4（192.168/10./172.16-31），生成候选 `access_url`，主页默认选第一个并渲染二维码。
- 多网卡 / VPN / VMware / WSL 虚拟网卡：PC 主页提供 **IP 下拉切换，二维码跟着变**，并标注网卡名辅助判断。
- 手机连不上时的两级方案：① 路由器给电脑 MAC 绑静态 IP（README 首推）；② mDNS 广播 `trans.local`（安卓浏览器支持不稳，仅作补充，不进 MVP）。
- 二维码只出现在 PC 主页和托盘菜单，内容为后端下发的 access_url，**不由前端推断**。

### 4.2 传输流（核心，合并原暂存架+剪贴板墙）

一条按时间倒序的混合流，条目 = 文本 | 文件副本 | 文件路径引用。

```
┌──────────────────────────────┐
│ 传输                          │ ← 顶部：断线状态条（可隐藏）
│ [文本输入框...............] [发送] │
├──────────────────────────────┤
│ 📄 设计稿v3.fig   12MB  10:32  │ ← 文件条目：缩略图/图标+名+大小+时间
│    [下载] [⋯]                 │
│ 💬 meeting 地址：xx 路…  10:30  │ ← 文本条目：点击复制
│ 🖼 photo_1024.jpg  2.1MB 10:28 │
│ 🎬 demo.mp4  01:23  10:25     │ ← 角标：⭕引用 / ◈副本
└──────────────────────────────┘
                          [⊕]   ← 全局上传按钮（悬浮）
```

**上架来源与落法（用户不需要理解内部区别，只看角标）：**

| 来源 | 落法 | 说明 |
|------|------|------|
| PC 网页拖拽 | **副本**：流式上传到服务端 `stage_cache/`，完成后上架 | 页面关了、重启了都能用；个人局域网带宽下这点拷贝成本忽略不计 |
| 右键"发送到 Trans"（SendTo） | **引用**：真实路径，服务端直接 ServeFile+Range | 零拷贝、体验最佳；文件被移走则条目标红 |
| 资源管理器 Ctrl+C 文件 | 弹轻提示"检测到复制了 N 个文件 [上架]"，**一键确认，不自动上架** | Ctrl+C 多数时候只是本地操作，全自动会烦 |
| 手机 ⊕ 上传 | 默认发到传输流（副本，落 `stage_cache/`）；可选指定目录 | 免选路径优先 |
| 任意端发文本 | 进流 | 见下 |

**文本双向闭环：**
- 手机端：点文本条目 = 复制（textarea+execCommand 兜底，见 §4.6 限制）。
- PC 端：文本条目按钮明确写 **"复制到电脑剪贴板"**，点击后有明确反馈（按钮变√/toast）——这是 PC 端最关键的动作，随后直接 Ctrl+V。
- **PC 复制的文字自动进流**（服务端轮询系统剪贴板，原生能力不受浏览器限制）：带防污染机制，见 §5.3。此能力 v0.2 上，MVP 先做"手动发送+一键写入"。

**条目操作**：下载/另存、在线打开（按类型分流）、复制链接、移除；（PC 端）"写入剪贴板"（文本）、"另存到…"/"打开所在文件夹"（文件副本）、"重新定位"（引用失效时）。

**生命周期**：清单持久化 `stage.json`；引用条目重启自动恢复；`stage_cache/` 副本默认保留（设上限如 20GB，超限托盘提醒清理）；文本保留最近 200 条。

**打包下载**：多选条目/文件夹 → 服务端流式 zip（不落盘打包），解决"20 张照片点 20 次"。

**缩略图与信息**：图片由服务端生成小图缓存（如 256px webp/jpg）；视频条目显时长（服务端抽或前端 `preload=metadata` 兜底），首帧抓取做不成就只显类型图标——不用完美，不能全是文件名。

### 4.3 文件浏览（兜底）

- 入口：底部"文件"Tab。文件夹优先排序、面包屑、最近打开、置顶星标目录。
- **搜索**：MVP 内置，按文件名搜共享根目录（服务端遍历/建轻索引）。
- 点击分流：视频→播放页；图片→预览滑动；文本→查看+复制；其他→下载；长按：下载/复制链接/**发到传输流**。
- **安全边界（轻但不能没有）**：所有文件访问限制在共享根目录内（解析后校验，防 `../` 穿越）；传输流的引用条目走**随机 ID**，真实路径不出现在任何下发给手机的 JSON 里。

### 4.4 上传（全局动作，不是 Tab）

- 右下角悬浮 ⊕：相册多选 / 拍照 / 文件选择；目的地二选一：**传输流**（默认）/ 指定目录。
- 每文件独立进度+速度，可取消，**失败单文件重试**（不整批重来）。
- 大文件分片上传 + 断点续传（v0.2；MVP 至少做到失败可续点重试）。
- 手机锁屏/切后台大概率断：上传中给"保持页面打开"提示条（http 下没有后台能力）。
- 服务端**上传前检查磁盘剩余空间**，不足直接返回明确提示。
- 同名冲突：不静默覆盖，弹 覆盖/自动改名/跳过。

### 4.5 视频播放

- Range（206）流式，mp4/webm/m4a 原生 `<video>`；引用与副本条目 alike。
- mkv/avi 标注"手机可能无法播放"+失败兜底；ffmpeg 转码远期。
- 进度记忆、倍速、同目录连播、srt 字幕 → v0.2+。

### 4.6 浏览器能力预期（http 非安全上下文）

明确降级，不写做不到的承诺：

| 能力 | 实际情况 | 对策 |
|------|----------|------|
| PWA/Service Worker | 不可用 | 只提供"添加到主屏幕"快捷方式，不做离线/后台承诺 |
| navigator.clipboard | 受限 | 复制一律点击触发 + `textarea+execCommand` 兜底 |
| File System Access / Wake Lock | 受限 | 不依赖；播放页常亮用 CSS/事件技巧兜底或放弃 |
| Notification | 不可用 | PC 通知用页面内 toast |
| 后台上传 | 不可靠 | 提示保持页面打开；分片续传兜底 |

自签 HTTPS 可解锁全部能力，但引入手机证书信任门槛，个人版**不优先**（记录在远期）。

## 5. 异常与状态设计（优先于顺利路径）

### 5.1 状态表

| 状态 | 手机端表现 | 可操作 |
|------|-----------|--------|
| 服务未启动 / IP 已变 | **独立断连页**（不是转圈） | 重新扫码说明、重试按钮 |
| 原文件被移动/删除（引用条目） | 条目标红"原文件已不在" | 移除；PC 端"重新定位" |
| 正在上传/下载 | 进度、速度 | 取消、失败重试 |
| 同名文件已存在 | 冲突弹层 | 覆盖 / 自动改名 / 跳过 |
| 磁盘空间不足 | 上传前服务端检查 | 明确提示剩余空间 |
| WS 断开 | 顶部小条"已断开，正在重连" | 重连后**全量同步**状态，不做增量猜 |
| 服务暂停（托盘操作） | 已打开页面切暂停页 | PC 端恢复即自动回来 |
| stage_cache 超限 | PC 托盘+主页提醒 | 一键清理最旧副本 |

### 5.2 剪贴板防污染与防回环

- 轮询去重：条目带内容 hash + 来源，同内容不重复上流。
- 文本长度上限（如 100KB），超长截断标记。
- **暂停键**：托盘与主页都有"暂停监听 10 分钟"（复制密码/验证码时不被上墙）。
- **防回环**：手机点"复制到电脑剪贴板"→ 服务端写入系统剪贴板 → 监听器必须识别"这是我们自己写的"（来源标记+hash 命中），不得当成新条目再上流。

### 5.3 其他高频细节

- Ctrl+C 文件：轻提示一键确认，不自动上架（见 §4.2）。
- 多文件/文件夹下载：多选 → 流式 zip。
- iOS Safari 下载存"文件"App，首次引导 toast。
- 手机端页面过期：所有条目操作前先探活，避免操作一个已失效的会话。

## 6. 页面结构总览

```
手机端 SPA（底部 Tab ×2 + 全局上传）
├── Tab1 传输   混合时间流：文本+文件（引用/副本角标）★首屏

└── 设置：端口 / 共享根目录 / stage_cache 上限与清理 / 剪贴板监听开关 / 开机自启
```

## 7. 技术方案

| 层 | 选型 | 说明 |
|----|------|------|
| 后端 | **Go** 单进程 | 单 exe；标准库覆盖静态文件+Range+multipart |
| 常驻 | systray + 注册表 Run 自启 | **非 Windows Service**（Session 0 问题） |
| IP 发现 | 枚举网卡筛私网 IPv4 | 下发 access_url 列表；mDNS（zeroconf）远期 |
| API | REST + WebSocket | REST：列表/上传/删除/暂存/缩略图/zip/搜索；WS：传输流实时同步+断线全量重同步 |
| 剪贴板 | Win32：文本轮询 + CF_HDROP（文件列表） | 文本自动进流 v0.2；CF_HDROP 轻提示 v0.2 |
| SendTo | `shell:sendto` 快捷方式 + 单实例 IPC（named pipe） | 参数=真实路径 → 路径引用上架 |
| 缩略图 | Go image 包生成小图缓存；视频时长 ffprobe 或前端 preload 兜底 | 不引重依赖，抓不到就图标 |
| zip 打包 | archive/zip 流式写，边遍历边写响应 | 多选/文件夹下载 |
| 分片上传 | PUT 分片 + 合并（v0.2） | 断点续传；MVP 先做失败单文件重试 |
| 前端 | 轻量 SPA（Vue3 或原生）+ qrcode.js 渲染后端下发的 URL | 无 SW/无剪贴板 API 依赖 |

关键实现点：
1. **Range**：`http.ServeFile` 原生支持（引用与副本统一走文件路径）。
2. **传输流同步**：WS 消息（add/remove/update）+ 客户端重连后 `GET /api/stream/full` 全量拉平。
3. **路径安全**：服务端所有文件读取先 `filepath.Clean` + 前缀校验；对外只暴露随机 ID。
4. **stage_cache**：独立目录+上限+LRU 清理；`stage.json` 持久化引用清单。
5. Windows 防火墙：首次运行引导；README 写明"网络被识别为公用网络时即使放行也可能连不上 → 切专用网络"。

## 8. 开源选型（结论不变：自研为主）

- [LocalSend](https://localsend.org)：无网页端，手机要装 App，不符合。
- Snapdrop/PairDrop：WebRTC+信号服务器，对纯局域网绕路。
- [filebrowser](https://github.com/filebrowser/filebrowser)：最全网盘，但无二维码/传输流/剪贴板，改造≈自研。
- [dufs](https://github.com/sigoden/dufs)：轻量底座，无传输流概念。
- [miniserve](https://github.com/svenstaro/miniserve)：`--qrcode --upload` 可临时凑合，不可定制。

差异化（传输流 + 引用/副本双落法 + 剪贴板闭环）没有任何现成品提供 → 自研。

## 10. 已知坑与 README 提示清单

1. **防火墙**：首次运行弹窗必须"允许"；**网络若被识别为"公用网络"，放行了也可能连不上 → 切"专用网络"**（README 故障排查第一条）。
2. **IP 漂移**：首推路由器 MAC 绑静态 IP；二维码每次启动重生成只是兜底。
3. **localhost 陷阱**：二维码 URL 必须来自后端网卡枚举，绝不能由前端 `location.href` 生成。
4. **Session 0**：绝不注册 Windows Service。
